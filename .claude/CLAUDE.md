# LightCycles (DuelTastic)

**This repo is DuelTastic, a pack of two-rider duel games, since 2026-10-25: read "Pack structure" below first.** Most sections after it were written when the repo was LightCycles alone and name its old paths (`src/app/game.tsx`, `src/app/lobby.tsx`, `src/components/...`, `src/hooks/...`, `src/redux/...`); that section's "Where the old paths went" maps them.

A local multiplayer Tron/lightcycles pass-and-play game (Expo/React Native, Skia-rendered). Part of the `@rific`/`@tastic`/InfiniteToken app ecosystem - depends on `@rific/auto-paper`, `@rific/feedback-press`, `@rific/focus-chain`, `@rific/gestures`, `@rific/splash-gate`, `@rific/toaster`, `@rific/updater`, `@tastic/achievements`, `@tastic/core`, `@tastic/edge-guard`, `@tastic/hud`, `@tastic/input`, `@tastic/profile`, `@tastic/split-screen`.

**Expo has changed.** Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code - don't rely on general Expo knowledge, this app is on SDK 57 specifically.

## Pack structure (DuelTastic, 2026-10-25)

App Review flagged LightCycles, Snake and Solitaire as spam (too many similar apps), so Jay is folding the fleet into packs. DuelTastic is LightCycles grown into three games in Home's order: **LightCycles**, **Turf** and **Tag**. Snake joins later (step 2 of the plan). The layout, the contract and the shell are PuckTastic's (see its CLAUDE.md, "Pack structure"), so read that too: what's below is what's different here.

**Layout.**
- `src/app/`: thin routes only. `index` (Home), `profiles`, `stats`, `loadout/[game]` and `play/[game]` (both with `generateStaticParams` over `games`, so the static web export has a page per game).
- **The game id comes second in a route, never first** (`loadout/lightcycles`, not `lightcycles/loadout`). expo-router strips the web build's base path off the front of an in-app link as well as the address bar (`stripBaseUrl` in its getStateFromPath), so under `WEB_BASE_URL=/lightcycles` a route starting with the game id `lightcycles` loses that segment and lands on `/loadout`, "Unmatched Route". PuckTastic had the same bug for Box Hockey under `/boxhockey` (tapping Box Hockey on Home landed on Unmatched Route, Air Hockey worked) and got the same route move the same day; `GameRoute.tsx` is identical in both.
- `src/pack.ts`: the pack's identity (`name: 'DuelTastic'`, `wordmark: ['Duel', 'Tastic']`, `colorCaption: 'DuelTastic only'`), `games` in Home's order, and the one store (`createPackStore`, keyPrefix `'dueltastic:'`).
- `src/shell/`: app-wide, imports no game. A copy of PuckTastic's shell (Jay, 2026-10-25: copy now, pull it out into a `@tastic/shell` package later). Kept as close to PuckTastic's as it can be so that's a diff, not a rewrite. What differs is pack settings, each to become an option when it moves: `seatColors.ts` (blue P1 `#2196f3`, red P2 `#f44336`, LightCycles' own; PuckTastic's are the other way round), `redux/shellState.ts` (the theme starts `appearance: 'dark'`), `components/HeroTitle.tsx` (LightCycles' light-trail wordmark with `HeroTitleTrails`/`heroTitleGeometry`, now for any two words, in place of PuckTastic's puck), `components/Fonts.tsx` (also loads Orbitron for the wordmark), `components/Theme.tsx` (also hands auto-paper `reanimated` and `fontFamily={MONO_FONT}`), `fonts.ts` (`MONO_FONT` from hud, plus `DISPLAY_FONT`), and nothing else: the route move above is in PuckTastic's shell too.
- `src/shared/`: code two or more games use, imports no game. PuckTastic's generic pieces (`playerSettings.ts`, `gameStats.tsx`, `SeatToasters`, `useUnlockToasts`, `useGameSound`, `lazySkia`), the power-ups every game shares (`powerups.ts`, `BoardPowerups.tsx`, `HeldPowerup.tsx`, and the CPUs' `distanceField.ts`, all from the old `src/games/shared/`), and two of DuelTastic's own:
  - `shared/match/`: a match, the same in every game. `types.ts` (`Player`, `Direction`, `GameMode`, `KeyScheme`, `RoundOutcome`, `humanPlayersFor`...), `constants.ts`, `MatchScreen.tsx` (the play screen's frame: the committed round frozen at mount, the board area measured once, the match record, recording a finished round's stats and toasting its unlocks; a game hands it its round component), `useMatchFlow.ts`, `MatchOverlays.tsx`, `OnboardingOverlay`, `RoundOverDialog`, `MatchOverDialog`, `RoundHistoryPips`, `TouchInputLayer(.web)`, `turnIntent`, `keyControls`, `playerZones`, `seatToastSpots`, `grid.ts` (start positions), `useDesktopWeb`, `loadout.tsx` (the grid size, speed, CPU and controls menus, `LoadoutOptionsRow`, `useKeySchemeControl`) and `guideCards.tsx` (the steering and two-player How to Play cards).
  - `shared/duelStats/`: LightCycles' stats and achievements engine, now every game's: a round in each ends the same way (one seat wins, or a draw), so the same stats, sections and milestones apply. `createDuelStats({ id, firstGameTitle })` gives a game its store slice (`<id>Achievements`), Provider, `useDuelStats().recordRoundOutcome`, and its `StatsSections`/`AchievementList`. Only the first achievement's name is the game's own: First Cycle, First Claim (Turf), First Chase (Tag).
- `src/games/<id>/`: each game, exported as one `GameDefinition` from its `index.ts`: `lightcycles/` (keeps its folders: `components`, `constants`, `hooks`, `redux`, `utils`), `turf/` and `tag/` (flat). Each has `settings` (createPlayerSettings), a guide slice and cards, `stats`, `useLoadout`, `PlayScreen` (its round component inside `MatchScreen`) and `art/` (its Home icon).
- **Every piece of code lives in one place. The shell and shared code never import a game, and a game never imports another game.** `eslint.config.cjs` enforces it (PuckTastic's file as is).

**Saved data.** The store is saved under `dueltastic:root`. Each game keeps its own keys: `<id>Settings`/`<id>Controls` (per player, see PuckTastic's "Loadouts follow the player"), `<id>Achievements`, `<id>Guide`, for `lightcycles`, `turf` and `tag`. Pack-wide keys are PuckTastic's (`appSettings`, `opponent`, `profileSelection`, `seatColors`, theme, haptic, sound, Keep Awake, profiles; `liveplay` never persisted). **Nothing is imported from LightCycles' own save** (`lightcycles:root`), which is left in storage unread: LightCycles was turned down by App Review, so no player has one to lose (Jay's call if that's wrong). `profileExtensions` (a profile's key scheme) is gone: a player's controls follow them through `<id>Controls`. Never change the prefix or a key once the pack ships. Pinned by `src/__tests__/store.test.ts`.

**Seat 2** is one button in every loadout (the CPU at a difficulty, Player 2 or a profile); no game here has Nobody. Each game's CPU difficulty is its own and seat 1's player's, with LightCycles' names (Drone, Bot, Mainframe). All three games seat 2 Player face to face on every device, the web included (`twoPlayerSeats: { faceToFaceOnWeb: true, followUpsideDown: false }`): the board is one fixed tall split.

**Each game's settings** are its own `Settings` type (LightCycles' `types.ts`, Turf's and Tag's `TurfSettings`/`TagSettings`): its own rules plus the speed, grid size, CPU level and `controlScheme` every game has (`keyScheme` was renamed `controlScheme`, the name `createPlayerSettings` needs). The lobby's Game picker and the `game`/`turf`/`tag` settings fields are gone; Turf's and Tag's options are top-level fields of their own settings. LightCycles' play screen adds the round's `gameMode` (`RoundSettings`) for `useGameState`.

**How to Play** is per game (PuckTastic's `createGameGuideSlice`, unseen for everyone). LightCycles keeps its three cards. Turf (4 cards: Steer Your Rider, Claim Your Ground, Cut Their Trail, two players; the third follows the crash rule) and Tag (3: Steer Your Rider, Don't Be It, two players; the second follows the rule) are new copy, with their own plain-View art (`GuideArt.tsx`), **for Jay to review**. Pinned by `src/__tests__/packGuides.test.tsx` (every game, every device and pair of controls and rule: 90-character bodies, art, Title Case, no em dashes, no keys/mouse on touch, no swipe on desktop).

**Home** (PuckTastic's): the Duel/Tastic light-trail wordmark, seat 1's button, one row per game. The blurbs: "The classic light-trail duel. Box the other rider in." / "Loop out from your ground to claim more. Cut their trail." / "The playground classic. Catch the other rider, then run." **Turf's and Tag's icons are placeholders** drawn in LightCycles' icon style (thick trails, white-ringed heads) until Jay draws them.

**Identity.** Unchanged for now: `app.json` (name LightCycles, slug, scheme, bundle ids, EAS project), the web path `/lightcycles`, `store.config.json`. Renaming to DuelTastic (and which App Store record the pack ships as) is Jay's call.

**Where the old paths went.** `src/app/game.tsx` is `src/shared/match/MatchScreen.tsx` plus `src/games/lightcycles/PlayScreen.tsx` (GameRound); `src/app/lobby.tsx` is the shell's `LoadoutScreen` plus each game's `useLoadout.tsx` (its `LobbySharedControls` is `shared/match/loadout.tsx`'s `LoadoutOptionsRow` and each game's own menus); `src/app/achievements.tsx` is the shell's `StatsScreen` plus `shared/duelStats/createDuelStats.tsx`; `src/app/index.tsx`, `profiles.tsx` and `_layout.tsx` are the shell's; `src/components/{MatchOverlays,OnboardingOverlay,RoundOverDialog,MatchOverDialog,RoundHistoryPips,TouchInputLayer}` and `src/utils/{seatToastSpots,playerZones,turnIntent,keyControls,grid}` and `src/hooks/{useMatchFlow,useDesktopWeb}` are in `src/shared/match/`; `src/components/{GameBoard,GameBoardHost,PowerupHud,GuideArt}`, `src/hooks/useGameState`, `src/utils/{arenas,cpuAi,floodFill,gameEngine}` and `src/constants/{game,guide,guideSteps}` are in `src/games/lightcycles/` (the match-wide constants moved to `shared/match/constants.ts`); `src/utils/{statsEngine,statsValidation}`, `src/constants/achievements` and `src/hooks/useGameStats` are `src/shared/duelStats/`; `AnimatedHeroTitle` is the shell's `HeroTitle`; `src/hooks/{useProfiles,useSettings}`, `src/redux/*`, `src/utils/{navigation,splashGate,gameParams}` and `Providers`/`Theme`/`Fonts`/`SettingsDialog`/`GuideHost`/`UpdateDialog` are the shell's. `src/constants/release.ts` stays put for the OTA tooling.

Always run `npm run lint` before finishing any task. This is an app (`"private": true`, no publish scripts) - `verify` doesn't include a build step.

**Builds and OTA updates:** the `build` and `update` scripts are plain `eas build` and `eas update`, with profiles in `eas.json` (`development`, `preview`, `production`). Pass the profile through, e.g. `npm run build -- --profile preview` or `npm run update -- --branch production --environment production --message "..."`. They used to be `@rific/updater`'s `rific-updater-build`/`rific-updater-update` bins, which @rific/updater 0.7.0 removed; the package stays for its OTA update hook. `build:web` is the one exception: it chains `npm run verify &&` before the web export (see "Web on games.infinitetoken.com" below).

## Tooling

Onboarded onto the shared `@infinitetoken` config packages (`eslint-config`, `jest-config`, `tsconfig`) - previously hand-rolled its own `eslint-config-expo`-based config, `jest-expo`-preset-direct config, and `expo/tsconfig.base`-extending tsconfig (the same pattern documented in [Swirlio](../Swirlio/.claude/CLAUDE.md)'s CLAUDE.md, which this migration followed).

`npx expo install --fix` + `npm update` were run as part of this pass too - confirmed clean: `npx expo install --check` reports up to date, `npm outdated` shows `Current === Wanted` for every dependency (remaining `Latest` values are all major bumps outside declared ranges, a deliberate-upgrade decision, not routine maintenance).

- `eslint.config.cjs` - `@infinitetoken/eslint-config/expo`, no local override
- `tsconfig.json` - `extends: "@infinitetoken/tsconfig/expo"`, keeps only the path-valued local bits (`paths`, `include`)
- `jest.config.cjs` - `@infinitetoken/jest-config/expo` with a `maxWorkers: '50%'` override (capping Jest's own CPU-count-minus-one default, which reliably triggers a "worker process has failed to exit gracefully" warning on this machine under multiple concurrent dev sessions) - `jest.setup.cjs` and `roots` are both auto-detected/defaulted (see below)

**`jest.config.ts` became `jest.config.cjs`, matching every non-Expo project in the fleet - no more `ts-node` gotchas.** This app (like every other Expo app) originally had `jest.config.ts` while every library/kit package used `.cjs` - a real divergence, not a justified one. `.ts` needed `import type {Config} from 'jest'` + a typed `const config: Config = ...` (a bare `export default createExpoJestConfig(...)` fails `tsc`'s declaration-emit check), plus a separate non-extending `tsconfig.jest.json` wired in via `TS_NODE_PROJECT=./tsconfig.jest.json` on `test`/`test:watch` (`ts-node`, Jest's `.ts`-config loader, can't resolve a tsconfig `extends` through a package's `exports` map at all). None of that exists for `.cjs` - plain `require()`, no transpilation, nothing to typecheck. Converting removed `tsconfig.jest.json`, the `TS_NODE_PROJECT` prefix on both scripts, and the `ts-node` devDependency entirely - see `@infinitetoken/jest-config`'s own README ("Why `.cjs`, not `.ts`") for the full history.

**`prettier.config.js` was deleted - `package.json` now has `"prettier": "@infinitetoken/eslint-config/prettier"` instead**, same as every library/kit package. The local file was a byte-for-byte duplicate of the shared package's own `prettier.cjs`; every Expo app had independently copy-pasted it rather than referencing the shared one.

**`metro.config.js` was deleted - it was unmodified `getDefaultConfig(__dirname)` boilerplate doing nothing.** Confirmed by removing it and running `npx expo export -p web`: builds cleanly, `canvaskit.wasm` still lands in `dist/` (copied into `public/` by the `setup-skia-web` postinstall script and served as a static file, fetched at runtime by `canvaskit-wasm`'s own init code - never `require()`d through Metro's bundler, so `resolver.assetExts` is irrelevant to it regardless). Swirlio never had this file at all and works the same way - this file's presence elsewhere in the fleet is boilerplate carried over from `expo customize`, not a requirement.

**Native/Expo module mocks moved from inline `jest.mock()` calls in `jest.setup.cjs` into individual `src/__mocks__/*.ts` files** - `react-native-reanimated`, `react-native-worklets`, `@expo/vector-icons` (+ its `createIconSet` deep import), `expo-splash-screen`, `expo-sensors`, `react-native-gesture-handler`, `react-native-safe-area-context`, `expo-router`. This is a fleet-wide convention change, not LightCycles-specific - see `@infinitetoken/jest-config`'s own CLAUDE.md for the full reasoning. `jest.setup.cjs` now holds only genuine setup-file content (the `IS_REACT_ACT_ENVIRONMENT` flag and `unhandledRejection`/`uncaughtException` handlers; the RAF/cancelAnimationFrame polyfills and no-factory `NativeAnimatedHelper` automock also carried over at the time were removed on 2026-10-02 as no-ops, see Testing) and is auto-detected by `@infinitetoken/jest-config/expo` - no `setupFilesAfterEnv` option needed at all. Also renamed from `.ts` to `.cjs` - a later, separate cleanup: auto-detection genuinely supports either (a `.ts` setup file goes through Jest's own test transform same as any other `setupFilesAfterEnv` entry, unlike `jest.config.cjs` itself, which Jest loads directly before any transform exists), but once its content shrank to thin boilerplate with the mock factories gone, there was no remaining reason for this one hand-authored config file to use a different extension than every other one in the app - see `@infinitetoken/jest-config`'s README, "Why `.cjs`, not `.ts`." With the mock factories' `any` usage gone, `jest.setup.cjs` no longer needs its own `no-explicit-any` eslint override - `eslint.config.cjs` is back to the plain one-liner. The one `any` this paragraph used to mention (bridging `requestAnimationFrame`'s polyfilled `NodeJS.Timeout` return type into `cancelAnimationFrame`'s DOM-lib `number` signature, under a targeted `eslint-disable-next-line`) lived in the RAF polyfill, which has since been removed as a no-op (see Testing) - `jest.setup.cjs` has no `any` left.

**One standing exception to "no `jest.mock()` call needed" (see Testing below): a *subpath* import.** Jest's manual `__mocks__` auto-pickup only ever matches a bare package specifier, never a deep import - confirmed empirically, not just in this repo (see Hangman's own `jest.setup.cjs`). `jest.setup.cjs` currently registers two: `@expo/vector-icons/createIconSet` (factory-less, delegating to `src/__mocks__/@expo/vector-icons/createIconSet.ts` - the mock content did move out as described above, but Jest still needs the explicit call to know to use it) and `@rific/feedback-press/audio` (inline factory, no adjacent `src/__mocks__/` file at all, since the stub is one line). Both are commented in place with the same reasoning; add a new one the same way if another subpath import ever needs mocking, rather than trying to force it through the bare-specifier auto-pickup path.

**The `modulePathIgnorePatterns: ['<rootDir>/.claude/worktrees/']` `overrides` entry this app previously needed is gone too, and not because it was removed by hand.** `@infinitetoken/jest-config/expo` now defaults `roots: ['<rootDir>/src']` (see its own CLAUDE.md - added specifically to make `src/__mocks__/` the manual-mock pickup location instead of the repo root). Since `.claude/worktrees/` lives outside `src/`, Jest's haste map scan never reaches it anymore either - confirmed directly: removing the override entirely and running the full suite produces no `jest-haste-map: Haste module naming collision` warning, with an active worktree still checked out in this repo. The `roots` default fixed this as a side effect, not the motivation for adding it.

## Drift audit and shared-package extraction (2026-09-17)

A fleet-wide audit today compared this app against its 4 siblings (AirHockey, BoxHockey, Pong, Snake) and found this app had drifted the most of the five - several real, app-specific bugs, all fixed below - plus pulled four pieces of now-duplicated code out into shared packages. Everything in this section is real, already-verified, uncommitted work in this repo's working tree, not a plan.

**Missing error-toast wiring.** This app had no `src/components/UpdateDialog.tsx` bridge at all - `_layout.tsx` imported and rendered `@tastic/hud`'s own `UpdateDialog` directly, with no `onError`, so an update-check failure (bad network, malformed manifest, etc.) was silently swallowed instead of surfaced. `SettingsDialog.tsx`'s `BaseSettingsDialog` had the identical gap on its own manual "Check for Update" path. Fixed by adding `src/components/UpdateDialog.tsx` - a thin bridge that calls `useToast().error('Update check failed', message)` from `@tastic/hud`'s `UpdateDialog`'s `onError`, same shape as AirHockey's/BoxHockey's/Pong's/Snake's own file of that name - and wiring `SettingsDialog.tsx`'s new `onUpdateError` prop the same way. Matches the fleet convention every sibling app already had; this app was the outlier.

**Root status bar ignored Lock Orientation.** `_layout.tsx`'s local `RotationAwareStatusBar` called `useOrientationState()` with no argument, so the real OS status bar's hide/show always tracked live device tilt regardless of whether the user had Settings' Lock Orientation toggle on. Fixed by threading `settings.lockOrientation` through, matching AirHockey's/BoxHockey's/Pong's/Snake's identical usage - then immediately superseded by the extraction below, which moved the component itself out of this app entirely.

**No settings/profiles splash gates.** Unlike AirHockey/BoxHockey/Pong, this app read `useGameSettings()`/`useProfiles()` immediately at mount with nothing waiting for their AsyncStorage/shared-App-Group-store reads to resolve - a cold-start race risking a flash of `DEFAULT_SETTINGS` or a stale/empty profile roster before the real values land. Fixed by adding `'settings'`/`'profiles'` gates to `src/utils/splashGate.ts` (now also exports `Gate: SplashGate`), a `loaded` field to both `GameSettingsProvider` (`useGameSettings.tsx`) and `ProfilesProvider` (`useProfiles.tsx`), and `SettingsGate`/`ProfilesGate` wrapper components in `_layout.tsx` - nested *inside* their respective providers' own position in the tree, not wrapping the providers from the outside, since an outside gate would deadlock (a provider blocked from mounting can never run the read that would flip its own `loaded` flag). Mirrors the other 3 apps' pattern exactly.

**Settings AsyncStorage all-or-nothing wipe (shared with 3 sibling apps).** `useGameSettings.tsx`'s stored-settings validation ran `isValidSettings` straight against the raw parsed blob, with no partial-merge path - so a blob saved before some `GameSettings` field existed was missing that field entirely, failed validation wholesale, and silently reset *every* other still-valid preference in it the moment a new field shipped. Fixed by merging the parsed blob onto `DEFAULT_SETTINGS` before validating: an old blob now only loses the field(s) it genuinely predates, and a field it does provide with the wrong type still rejects the merge exactly as before.

**`Theme.tsx` marked its `'theme'` splash gate ready immediately instead of waiting for `AutoPaperProvider`'s own `onReady`.** Found while auditing BoxHockey's identical bug: this app's `Theme.tsx` called `useSplashReady('theme', true)` unconditionally right after reading the Redux `theme` slice, reasoning that `PersistGate` already resolving `settings` was enough - but `AutoPaperProvider` itself still renders `null` internally until it's actually computed a theme object from that settings value, a separate, later step. Marking the gate ready before that could let the splash screen lift while `AutoPaperProvider` was still rendering `null` underneath it. Fixed to match AirHockey's/Pong's own `Theme.tsx`: `const onReady = useCallback(() => markSplashReady('theme'), [])` passed to `<AutoPaperProvider onReady={onReady}>`.

**Face-to-face achievement toast rotation - the reference, not a fix.** This app's `profileUnlockToast` state (`game.tsx`), threaded into `RoundOverDialog`/`MatchOverDialog` as per-seat achievement badges correctly oriented per seat, was never broken here - it's the pattern BoxHockey's/Pong's/Snake's own equivalent fixes this session were modeled on. Nothing changed in this app for this item; noted here only so the drift audit's scope reads as complete. (Superseded 2026-10-20: 2 Player unlocks are toasts turned to face each seat; see "Unlock toasts" at the end.)

**A sixth, LightCycles-only fix found while auditing this repo (not part of the fleet-wide comparison above): a lobby seat's manual color override on a profile-selected seat didn't survive navigation.** `lobby.tsx`'s `handleSeatColorChange` used to skip persisting anything for a seat currently tethered to a profile (see `persistSeatColor`'s own doc), which meant a manual recolor or clash-swap on that seat was nothing more than whatever the `theme` slice happened to already be showing - no persisted state behind it at all. The very next mount of this screen (leaving and coming back, not just a real profile reselect) had nothing to fall back on except the mount/reapply effect's own unconditional `profile.color`, so the override silently vanished. ## Settings and Lock Orientation (2026-10-07)

**Settings live in Redux**, like every other persisted value: `src/redux/settingsSlice.ts` (`DEFAULT_SETTINGS` plus `@rific/core`'s `createSettingsSlice('settings', { initializeMode: 'merge' })`), read and written only through `useSettings()` (`src/hooks/useSettings.ts`, returning `{ settings, setSettings(patch) }`). ## OS portrait lock (2026-10-08)

The OS is locked to portrait on every device and the app draws all rotation itself (`@tastic/core`'s `OrientationProvider` reads the accelerometer). `@tastic/core`'s Expo config plugin (`"@tastic/core"` in `app.json`'s `plugins`) owns every native setting that depends on: `orientation: "portrait"`; `ios.requireFullScreen` plus a Portrait-only iPad orientation list (audit F009: without it Expo forces all four iPad orientations, so iOS turned the screen on top of the app's own rotation, and Split View, Slide Over and Stage Manager are the price); and `android:appCategory="game"` (Android 16 and later ignore the portrait lock on tablets and unfolded foldables, except for games). Don't set any of those by hand here, and don't add `expo-screen-orientation` (it re-enables upside down on home-button iPhones). The why behind each is in @tastic/core's README. Check the result with `npx expo config --type introspect`; it only takes effect in a new native build.

## Status bar: per-screen options (2026-10-15)

The OS status bar is set through react-native-screens' screen options, never a `StatusBar` component. `_layout.tsx`'s `AppStack` (identical across AirHockey, BoxHockey, LightCycles and Pong) spreads `@tastic/core`'s `useRotationAwareStatusBar()` (0.14.0+) into the root Stack's `screenOptions`, which hides the bar while the content is rotated off portrait (no `locked` argument: `OrientationBridge` freezes the reading it follows), and /game hides it for the whole round through its own `Stack.Screen` options (`GAME_OPTIONS`, `{ statusBarHidden: true }`), set in the layout so they apply as the screen is pushed rather than one effect later. No style is passed: react-native-screens' default (`auto`, following the system appearance) is what expo-status-bar's `auto` gave before.

Why: an app linked against the iOS 27 SDK (Xcode 27) can't set the status bar through `UIApplication` any more (UIKit's `UIApplication.h`: setting it "does nothing if ... linked against SDK versions 27.0 or later"), and that is all React Native's `StatusBar`, and so expo-status-bar, does on iOS. `@tastic/core`'s config plugin now sets `UIViewControllerBasedStatusBarAppearance: true`, which react-native-screens needs, and under which every mounted `StatusBar` logs an `RCTLogError` (a red box in dev). So nothing may mount one: `<RotationAwareStatusBar />` (removed from core) and /game's `<StatusBar hidden />` are gone, `Theme.tsx` passes auto-paper's Provider `statusBar={false}` (0.13.2+, which also covers `Appbar.Header`), and expo-status-bar is no longer a dependency or an app.json plugin (its plugin did nothing without options). Pinned by `src/__tests__/statusBar.test.tsx` (no source file imports expo-status-bar or React Native's `StatusBar`; Theme turns auto-paper's off).

- **The hide only shows in a Release build.** In a dev-client (development) build, expo-dev-launcher inserts its own view controller above react-native-screens' stack, so the screens' status bar options never reach UIKit and the bar never hides there, rotated or on /game (see @tastic/core's CLAUDE.md, "Status bar: per-screen options"). Check it in a preview/production build or a local Release build.
- **It needs a new native build.** `UIViewControllerBasedStatusBarAppearance` only reaches Info.plist at prebuild, and the app.json plugin list changed too, so the fingerprint runtime version moves on: an OTA update from here on won't reach an older binary.
- Android gets the same options from react-native-screens (no Info.plist key there). Not checked on a device on either platform.

## Gesture worklets leaked the screen through runOnJS (2026-10-18)

`TouchInputLayer`'s Pan and Tap worklets called `runOnJS(handleTurn)` and `runOnJS(handleActivate)`. react-native-worklets holds a runOnJS target from native code (a Hermes GC root) for as long as the worklet's cached copy lives, and that copy lives as long as the component holds its Gesture, so the component's own callbacks pinned it in memory forever (found in Solitaire, where every dealt card leaked). Fixed with `@rific/core` 0.5.0's `useWorkletCallback` (a stable key per callback) and `callWorkletCallback` (module level): the worklets call `scheduleOnRN(callWorkletCallback, key, player, direction)`. The keys are stable, so the ref-based gesture stability described above is unchanged. `OnboardingOverlay`'s `withTiming` completion is a one-shot the component does not keep, so it calls `scheduleOnRN(onComplete)` directly. Not verified on a device or with heap snapshots. JS only, so it can ship in an OTA. Both files import `scheduleOnRN` from `react-native-worklets` now (reanimated 4 deprecates `runOnJS` in its favor), so there is no `runOnJS` left in `src/`.

## Turf (2026-10-24)

DuelTastic's first new game (the pack Jay is folding Snake, LightCycles, Turf and Tag into after App Review flagged the single games as spam), built in this repo until it takes the pack layout. Everything Turf owns is in `src/games/turf/`, imports nothing from another game (LightCycles' `utils/grid.ts` start positions and `constants/game.ts` cell sizes aside, which move to `shared/` with the pack; what every game's powerups share comes from `src/games/shared/`), and moves into the pack unchanged.

- **Rules (Jay, 2026-10-24):** each rider starts on a 7 x 7 square of its own ground. Leaving it lays a trail; getting back claims the trail and everything it encloses, the other rider's ground included (`capture.ts`: a fill in from the board's edge with the rider's ground and trail as walls; the edge itself is no wall). Riding into the other rider's trail crashes them, into your own crashes you (unless Cross Your Own Trail is on), the edge crashes you, and two heads meeting go to whoever's ground the meeting cell is (a draw on nobody's). Crash Ends Round is the classic rule; Crash Sends Home loses the trail and keeps playing. A rider whose ground is all taken is suffocated. The clock (1, 2 or 3 minutes) gives the round to more ground. Two claims landing on one tick: the bigger goes first, so the tighter loop keeps any overlap.
- **Pieces:** `engine.ts` (pure, 51 tests), `cpu.ts` (plans a loop each time it's home, heads home when its trail is threatened, cuts yours when it can; aggressive always on hard, half the time on normal, never on easy), `useTurfState.ts` (the round on an animation-frame loop that steps by elapsed time, so its speed doesn't depend on the display's refresh rate (TODO F065's problem); the CPU's plan lives in its state), `TurfBoard.tsx` with its `TurfBoardHost` web pair, `TurfHud.tsx` (each player's share, the other's, the clock and what they're holding at their own edge), `TurfRound.tsx`.
- **Powerups (Jay, 2026-10-24):** the loadout's Powerups row (Turf's own `powerups` setting, off by default) picks which can turn up. Turf's names for the effects every game shares, with the same colors and icons (`TURF_POWERUP_EFFECTS` maps each onto the shared effects, see "Shared between the new games"): Dash (yours, double speed: Overdrive), Frost (theirs, frozen: Stasis), Mud (theirs, half speed: a cell every other tick, a longer, softer Frost), Fence (yours: nothing but the board's edge crashes you, nobody can cut your trail, you can cross your own, a head-on never takes you out: Shield), Tangle (theirs, reversed steering: Hack), Gust (theirs, forced double speed: Overclock), and Turf's own Sod (yours: the 5 x 5 around your head becomes yours, and out on a trail it brings you home, claiming the trail and whatever it closes off; icon `grass`). Durations in `TURF_EFFECT_TICKS` (about 2.5s Dash, 1.5s Frost, 3s Mud, 4s Fence, 2s Tangle and 2s Gust at the normal speed). As in LightCycles: one mystery box on the board at a time, a new one the tick after it's taken, picked up by passing within a cell, one held at a time (a new one swaps it), used with a tap or the scheme's powerup key, the type shown only in the holder's badge, a ring around the head per effect. Unlike LightCycles, a box turns up about as far from both heads as each other (within 2 steps), not much further than it has to (`PICKUP_SPREAD`), on nobody's ground when it can, off the outer two cells, and never next to a trail. `tickTurf` now runs a tick in steps (two under Dash or Gust, none frozen), checked one at a time, so a fast rider can't skip a trail or a pickup; a frozen rider keeps its queued turn, and riding into one counts as a head-on on its ground or a cut out on its trail. Tangle reverses a person's swipes and keys in `TouchInputLayer` (`controlInverted`), like Hack.
- **The CPU and powerups:** it reads the board in ticks (a sped-up or frozen rider at its real speed), checks every cell it covers in a tick, rides out for a box when it holds nothing (up to 24 steps on normal, 36 on hard, never on easy), goes for a frozen rider's trail, and uses what it holds (`shouldTurfCpuActivate`): every level reaches for Fence, Sod, Frost, Mud or Dash when its trail could be cut before it gets home; normal and hard also wait for each one's moment (Sod and Dash on a long trail, Frost or Mud when it can reach your trail while you're frozen or slowed, Tangle while you're out, Gust near an edge or on a long trail); otherwise a 1-2% chance a tick. Under Tangle it makes up for the reversal as LightCycles' CPU does (hard always, normal 60%, easy never). `cpu.test.ts` plays CPU-against-CPU games with every powerup on and checks none crashes into its own trail or the edge without a Tangle forcing it.
- **One match flow for both games:** `hooks/useMatchFlow.ts` (`useMatchControls` before the game's state hook, `useMatchFlow` after it) and `components/MatchOverlays.tsx` are what `GameRound` used to hold inline: the dialogs and pause, Keep Awake, the result card's timing, Play Again agreement, Quit, the sounds, Edge Guard. `GameRound` and `TurfRound` both use them. `backgroundPause.test.tsx` drives the real `useMatchControls`.

## Tag (2026-10-24)

DuelTastic's second new game, built beside Turf in `src/games/tag/` on the same terms: its engine, CPU and board import nothing from another game except LightCycles' start positions (`utils/grid.ts`) and `@/types`' speed and grid-size tiers (both moving to `shared/` with the pack) and `src/games/shared/`, and its round screen sits in the same match flow and input layer as Turf's.

- **Rules (proposed 2026-10-24, for Jay to play and change):** one rider is It. It coming within a cell of the other rider (diagonally included: the heads are drawn wider than a cell) makes them It. The new It stands frozen for `TAG_FREEZE_TICKS` (about 1.5s) while the old It gets away, and can't tag until then (no tag-backs). It rides 15% faster (`TAG_IT_SPEED`, kept exact in hundredths of a cell) so a chase can end on an open board. Nothing crashes: the edge and the pillars stop a rider, a turn into one waits until the way opens and is taken then (Pac-Man's buffered turn), and with no trail a rider can turn straight back. The seats take turns starting as It, seat 2 first (so in Vs CPU the player runs first). Rules: Hot Potato (whoever's It at the buzzer loses, the default) or Least Time It (less time as It wins, the same is a draw). Arena: Pillars (2 x 2 blocks on a lattice centered on the board and mirrored end to end, a 3-wide middle one where the length can't center a 2-wide one, none on or next to a start) or Open. Round: 30s, 1 or 1½ minutes (default 1).
- **Pace:** Tag's cells are big (`TAG_CELL_PX`: 16, 22 or 30px by the shared grid size, about 17 x 38 cells on a phone) and its speed is cells a second, not scaled to the cell (`TAG_SPEED_INTERVAL_MS`: 150, 115 or 90ms). In CPU-against-CPU games on a phone-size board, a tag comes every 3 to 23 seconds depending on the levels.
- **The CPU:** As It it takes the shortest way round the pillars to the other rider, or to where they're headed (2 cells ahead on normal, 4 on hard). Running, easy just keeps away (and runs into corners); normal and hard head for the cell It would take longest to reach of those they can get to first, counting It's speed and any freeze left, so they circle pillars and double back. An earlier try that headed for the most board it could reach first ran toward It and lasted less than easy; the tests pin the ranking (a hard runner lasts longer than an easy one, a hard It catches sooner than an easy one, and tags keep coming).
- **Powerups (2026-10-24, Jay asked for them):** the loadout's Powerups row (Tag's own `powerups` setting, off by default). Dash (yours, double speed), Freeze (theirs: they stand still, and a frozen It can't tag), Mud (theirs: half speed for about 3s, a longer, softer Freeze; a slowed It can still tag; Jay's idea in place of a forced speed-up, 2026-10-24, and added to Turf too), Safe (yours: nobody can tag you for about 3s; only while you're running, so tapped as It it stays held for later) and Tangle (theirs, reversed steering), on the shared effects (boost, freeze, slow, shield, reverse; `TAG_POWERUP_EFFECTS`, durations in `TAG_EFFECT_TICKS`). No Gust: with nothing to crash into, a forced speed-up only helps its target. The boxes, held slot, rings and Tangle's reversed input work as in Turf, all through `src/games/shared/`; a box's footprint keeps clear of pillars. It's 15% and Dash's double multiply. The CPU uses Safe, Freeze, Mud or Dash to get away when It is about to tag it (within 3 steps), and on normal and hard also Freeze, Mud and Dash as It to catch (within 12, 16 and 10 steps) and Tangle when the other rider is near; it rides for a box when it holds nothing (up to 10 steps on normal, 16 on hard; as It only when the box is much nearer than the runner, running only when it gets there well before It), counts Safe, Dash and Freeze when it runs, and makes up for Tangle as Turf's does.
